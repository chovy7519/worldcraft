# WorldCraft V0.6 · 复合多边形、曲线路段与平面交叉口

## 范围与设计原则

V0.6 继续使用局部米制 X/Z 平面，不引入线上地图、3D 地形或外部几何运行时依赖。与 V0.5 的主要区别：**可编辑道路边**允许二次 Bézier 弯曲；下游地块不再必须表示为一块凸多边形，而可用一个具有**外环 `outer`、内洞 `holes[]`、精确凸分片 `cells[]`**的复合对象表示。

不要混淆三种几何：
- `outer` / `holes[]`：用于地块的语义边界、边界净距、面积与正式 ID；这是可凹、可带洞的**单一用地对象**。
- `cells[]`：精确铺砌的凸分片，用于局部裁切、三维三角化、保守建筑基底和几何碰撞，**不是独立地块**。
- `bounds`：仅是包围盒，用于 UI 与查询加速，**不能用于实际碰撞或退界判定**。

## 道路 Schema V2

```json
{
  "version": 2,
  "nodes": [{"id":"N-0","x":0,"z":0}],
  "edges": [
    {"id":"E-0","from":"N-0","to":"N-1","kind":"local","width":10,"bend":8}
  ]
}
```

上例仅说明边字段，节点未列全，不是可直接导入的完整网络。`bend` 的单位是 m，表示中点相对于直线弦的**实际侧向偏移**：0 为直线，负值弯向反侧，范围 [-30, 30]。二次 Bézier 控制点位于弦中点沿左法线的 `2 × bend` 处（因此曲线在 t=.5 处偏移 bend）。

`sampleRoadCurve` 按长度和 bend 自适应离散，每条曲线最多 24 个线段；全场最多 12 条曲线。每条采样弦先获得道路宽度生成凸走廊，连接处采用 12 边形平面交叉帽（joint caps），再逐次裁掉尚未被占用的地面：**既能形成连续道路面，又不会产生重叠的道路占地分片**。

道路交叉按二维拓扑 noding 处理，相交的道路默认在同一标高连接，不表示真实转弯半径、信号配时、立交桥或路口规范。

### 编辑命令

- 道路编辑器中选择 `E-10`，把“曲线中点偏移”改成 `8`；
- 离线自然语言输入 `路段 E-10 弯曲设为 8m`；
- 输入 `路段 E-10 弯曲设为 0m` 恢复直线。

V0.6 对曲线路段的拆分和曲线中间节点的合并暂时拒绝，防止用不等价的线型代替原曲线；曲线可移动端点或修改路幅，并保留同一边的稳定 ID。

## 复合区域结构与多边形布尔约束

```ts
type CompoundRegion = {
  id: string;
  outer: [number, number][];     // 单一外环
  holes: [number, number][][];   // 0..n 个内洞
  cells: [number, number][][];   // 无重叠的凸分片
  vertices: [number, number][]; // 向前兼容：同 outer
  area: number;
  bounds: {x0:number; z0:number; x1:number; z1:number};
};
```

引擎的 `mergeConvexCells` 并不是无约束通用 GIS 布尔运算。它要求**输入是已经正确铺砌、不存在正面积重叠的凸多边形**。先将共线边细分为同一组原子边，取消相互反向的内部边，再追踪封闭环，生成一个外环和若干内洞；仅以**共享正长度边**判断连通，不会把仅顶点接触的区域错误合并。面积校验：`Σ area(cells) ≈ area(outer) − Σ area(holes)`。

地块分割的次序是：道路有限占地 → 剩余凸单元 → 边连通聚合为街区 → 对凸单元执行一致的地块分割 → 按边连通聚合为单个复合地块 → 分配功能 → 建筑/公园/树木。

- 建筑依然从地块内某一块满足退界的凸子单元生成，以避免越过凹角或侵占洞口。此策略**保守，不是对复杂地块最大可建面积的优化**。
- 公园沿用复合地块的外环和内洞，渲染器逐凸分片填充，因此不会将孔洞错误填实。
- 树木通过 `regionContains(parcel, point, radius)` 同时检查外边界与洞边界净距，此外避让道路、建筑与其他树冠。
- 对非凸多边形的相交判断使用三角化后的凸分片；正式场景统一使用预存的 `cells[]` 进行完整冲突检查。

## 计算依赖与输入输出

| 阶段 | 输入 | 输出及校验 |
|---|---|---|
| 1. 道路拓扑 | `RoadNetwork V2`, 场地边界 | 节点/路段、曲线采样、交叉关系与端点合法性 |
| 2. 占地生成 | 道路中心线、宽度、joint caps | 不重叠道路面 `roads[]` |
| 3. 地块 | 剩余凸单元、目标地块尺度 | `blocks[]`, `parcels[]`: 单一复合对象含 rings/cells |
| 4. 功能 | 地块、绿地概率、中心规则 | 用地功能 `residential / commercial / civic / park` |
| 5. 建筑与公园 | 功能、退界 | 可验证建筑凸基底；与建筑互斥的完整公园对象 |
| 6. 树木 | 临路边、边界、建筑、道路 | 避让外界/内洞/道路/建筑/树冠的 `trees[]` |
| 7. 实例与导出 | 前述全部，世界 Seed | 3D 场景、稳定 ID、JSON 规则与版本 |

前置的地形、水系扩展槽不变；一旦启用必须在道路和地块生成之前改变 `buildableMask/roadConstraints`，不能只在渲染后裁切。

## 几何验证与局限

`npm run verify` 运行 Node 测试、构建并执行空间检查。V0.6 增加的测试覆盖凹多边形单对象聚合、闭合内洞与面积扣除、洞口避让、旧版道路 V1 迁移、曲线几何端点/中点、曲线与下游 PCG 的确定性、非法曲率/拆分的拒绝及 15 组曲率 × Seed 的空间冲突检查。

**尚未实现**：用户任意手绘凹地块和孔洞、自由多输入布尔运算、真实 B-spline/NURBS 线形、圆曲线/缓和曲线规范、桥隧多层拓扑、完整的建筑退界最优多边形内缩、GIS 坐标系/精度鲁棒性认证。场景中可以出现凹地块；含洞算法有独立合成用例，但默认城市不保证自然生成带洞地块。
